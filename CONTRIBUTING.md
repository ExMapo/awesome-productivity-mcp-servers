# Contributing to Awesome Productivity MCP Servers

Thank you for your interest in contributing to **Awesome Productivity MCP Servers**.

This repository is a community-curated directory of useful **Model Context Protocol (MCP) servers, clients, frameworks, and related tools** that help people work more effectively with AI.

The goal of this project is to make it easier for users to discover high-quality MCP tools for productivity, knowledge work, research, collaboration, automation, communication, planning, development, and other practical workflows.

We welcome contributions from MCP developers, product teams, open-source maintainers, researchers, AI enthusiasts, and community members.

## Ways to Contribute

You can contribute in many ways.

### Add a new MCP server

If you discover or maintain a useful MCP server with a clear productivity use case, you can submit it through a pull request.

### Update an existing listing

You can update:

- Project descriptions
- Official links
- Repository URLs
- Documentation URLs
- Project names
- Categories
- Availability information

### Fix broken links

If a project has moved, changed domains, or renamed its repository, please submit the correct official link.

### Improve descriptions

Some listings may be too vague, outdated, or overly promotional. Contributions that make descriptions clearer and more factual are welcome.

### Suggest a new category

If several useful MCP tools do not fit any existing section, you may propose a new category.

### Report inactive projects

If a listed project has been deleted, discontinued, or is no longer MCP-related, open an issue or submit a pull request.

### Improve repository documentation

Contributions to the README, contribution guide, templates, organization, and general usability are welcome.

## What Belongs in This Repository

A project should normally meet all of the following requirements.

### MCP relevance

The project should:

- Implement the Model Context Protocol
- Provide an MCP server
- Provide an MCP client
- Provide an MCP framework, SDK, gateway, or utility
- Provide an official integration that clearly supports MCP

### Productivity relevance

The project should help users or AI agents perform practical work.

Examples include:

- Mind mapping
- Knowledge management
- Research
- Note-taking
- Project management
- Task management
- Calendar management
- Meetings
- Email
- Team communication
- Document processing
- File management
- Browser automation
- Workflow automation
- Developer productivity
- Data analysis
- Content management
- Personal knowledge
- Scheduling
- Collaboration

### Publicly verifiable

The project should have at least one public source that allows maintainers to verify what it does.

Preferred sources:

1. Official GitHub repository
2. Official documentation
3. Official product website
4. Official MCP page

## What We Usually Do Not Accept

The following submissions may be rejected.

### Non-MCP tools

General AI tools that do not support MCP should not be submitted.

### Pure promotional pages

A landing page with no clear MCP implementation, documentation, or public evidence may not be enough for inclusion.

### Affiliate or referral links

Please use official URLs only.

Do not use:

- Affiliate links
- Referral codes
- Tracking links intended for commission
- URL shorteners

### Duplicate projects

Do not submit a project that is already listed unless you are correcting or improving the existing entry.

### Misleading descriptions

Descriptions should explain what the project does without exaggerated marketing claims.

### Unrelated projects

The repository focuses on productivity and practical AI workflows. Projects with no meaningful productivity use case may be declined.

### Clearly abandoned or broken projects

A project whose repository and documentation are unavailable may not be accepted.

## Before You Submit

Before opening a pull request:

1. Search the README for the project name.
2. Search for alternate spellings or previous project names.
3. Confirm that the main link works.
4. Confirm that the project is MCP-related.
5. Choose the most appropriate category.
6. Write a concise factual description.
7. Add the listing alphabetically within the section.
8. Avoid unrelated changes in the same pull request.
9. Use an official source whenever possible.

## How to Add a New MCP Server

### Step 1: Fork the repository

Create your own fork of the repository on GitHub.

### Step 2: Create a new branch

Use a clear branch name.

Examples:

```text
add-example-mcp
update-notion-mcp
fix-broken-calendar-link
add-research-category
```

### Step 3: Edit the README

Add the project to the most appropriate section.

### Step 4: Keep alphabetical order

Place the project in alphabetical order by project name.

### Step 5: Commit your changes

Use a clear commit message.

Examples:

```text
Add Example MCP
Update Example MCP description
Fix Example MCP repository link
```

### Step 6: Open a pull request

Complete the pull request template and provide enough information for maintainers to verify the submission.

## Listing Format

Please use the following Markdown format:

```markdown
- **[Project Name](https://example.com)** — Short factual description of what the MCP server does.
```

Example:

```markdown
- **[Example MCP](https://github.com/example/example-mcp)** — Manage tasks and projects directly from MCP-compatible AI assistants.
```

Use an em dash (`—`) between the project link and description when possible.

---

## Writing a Good Description

Descriptions should answer:

> What does this MCP project allow an AI assistant or user to do?

### Good description

```text
Connect AI assistants to ExampleApp for task and project management.
```

### Also good

```text
Search and organize documents stored in ExampleApp through MCP.
```

### Avoid promotional wording

```text
The world's best MCP server for productivity.
```

```text
The most powerful AI automation tool ever built.
```

```text
The #1 MCP solution for every user.
```

### Description style

Descriptions should be:

- Concise
- Factual
- Neutral
- Specific
- Easy to understand
- Based on publicly verifiable features

Try to keep descriptions to one sentence.

## Official and Community Projects

Both official and community-maintained MCP projects are welcome.

### Official project

An official project is maintained by the company or organization responsible for the underlying product or service.

### Community project

A community project is independently maintained and connects MCP to another platform, API, application, or workflow.

Whenever possible, use the official repository or documentation URL.

Do not describe a community implementation as official unless there is clear evidence that it is maintained by the relevant company or organization.

---

## Alphabetical Ordering

Listings should be alphabetized within each category by project name.

Example:

```markdown
- **[Alpha MCP](...)** — ...
- **[Bravo MCP](...)** — ...
- **[Charlie MCP](...)** — ...
```

Do not place your own project at the top of a category for additional visibility.

The purpose of alphabetical ordering is to keep the list fair and easy to browse.

---

## Duplicate Listings

Before adding a project, search the entire README.

Check:

- Project name
- Company name
- Previous project name
- GitHub organization
- Product name

If the project is already listed, update the existing entry instead of adding another identical listing.

---

## Multiple Categories

A project may appear in more than one category when it provides clearly different and meaningful functionality.

For example, an MCP project may reasonably belong in both:

- Calendar & Scheduling
- Tasks & To-Do Management

However, avoid adding the same project to many categories simply for visibility.

Maintainers may remove duplicate category placements if they do not add meaningful value.

## New Category Requests

You may propose a new category when existing categories do not fit.

A useful category should:

- Have a clear purpose
- Be related to productivity or practical AI workflows
- Be broad enough to include multiple projects
- Not heavily duplicate an existing category
- Have a simple and understandable name

Examples of possible future categories:

- CRM & Sales Productivity
- Marketing Productivity
- SEO
- Education
- HR & Recruiting
- Customer Support
- Design Productivity
- Personal Finance
- Knowledge Bases
- AI Agents
- Personal Assistants

If you are unsure, open an issue before creating a large new section.

## Updating an Existing Listing

Updates are welcome when:

- The project moved to a new repository
- The official website changed
- The product was renamed
- The old description is inaccurate
- The project gained official MCP support
- The project is no longer official
- The current category is incorrect

When opening the pull request, briefly explain why the update is needed.

---

## Removing a Project

A project may be removed when:

- Its main link is permanently unavailable
- The repository was deleted
- The project no longer supports MCP
- The project was replaced by another official implementation
- The listing is misleading
- The project is unrelated to productivity
- The project is primarily spam
- The project appears fraudulent
- There is no longer enough public information to verify it

A project should not automatically be removed only because it has not received a recent commit.

Some stable MCP tools may remain useful without frequent updates.

---

## Link Quality

Use the most authoritative link available.

Preferred order:

1. Official GitHub repository
2. Official MCP documentation
3. Official product documentation
4. Official website

Avoid:

- Blog posts describing the project
- Third-party directory listings
- Search result pages
- Affiliate links
- Shortened URLs
- Tracking-heavy campaign links

## Pull Request Guidelines

Please keep each pull request focused.

### Good pull request

```text
Add Example MCP to Project Management
```

### Less useful pull request

```text
Add 25 unrelated projects, reorganize the README, rewrite the introduction, change categories, and modify contribution rules
```

Large cleanup contributions may be appropriate, but please discuss major structural changes in an issue first.

### Pull request title examples

```text
Add Example MCP
Update Example MCP
Fix Example MCP link
Add Calendar Productivity category
Remove discontinued Example MCP
```

## Review Process

Every pull request may be reviewed for:

- MCP relevance
- Productivity relevance
- Link validity
- Description quality
- Correct category
- Duplicate entries
- Alphabetical ordering
- Promotional language
- General usefulness

Maintainers may:

- Request changes
- Edit descriptions for consistency
- Move the listing to another category
- Ask for an official source
- Ask for evidence of MCP support
- Close duplicate submissions
- Decline low-quality or off-topic submissions

Submission does not guarantee inclusion.

---

## Quality Standards

The goal is not to list every project that mentions MCP.

The goal is to maintain a useful, trustworthy, and discoverable list.

Maintainers may consider:

- Clear documentation
- Public source code or official documentation
- Real MCP support
- Usable installation instructions
- Clear purpose
- Relevance to productivity
- Project accessibility
- Evidence that the project exists and works as described

Popularity, star count, company size, or commercial status are not required for inclusion.

---

## Community Conduct

Please keep discussions respectful and constructive.

When reviewing or discussing a submission:

- Focus on the project and contribution
- Avoid personal attacks
- Avoid hostile language
- Explain requested changes clearly
- Assume good faith when possible
- Respect maintainer decisions

Disagreements about inclusion, categories, or wording should remain focused on improving the repository.

---

## Helping Maintain the Repository

We welcome contributors who want to help keep the list current.

Useful maintenance work includes:

- Reviewing pull requests
- Checking broken links
- Finding new MCP projects
- Identifying duplicates
- Updating outdated descriptions
- Improving category organization
- Reviewing inactive projects
- Improving documentation
- Helping new contributors

If you would like to become a regular contributor, open an issue and introduce yourself.

## Questions

If you are unsure whether a project qualifies, which category to use, or how to format your submission, open an issue before creating the pull request.

Thank you for helping make **Awesome Productivity MCP Servers** a useful resource for the MCP community.
